## 2. 固定测试集（30 例）

文件：`eval/cases.json`；执行器：`eval/harness.py`。

```bash
export LLM_API_KEY=...          # 仅环境变量，不入库
python -m eval.harness --output evidence/real-model
```

| 类别 | 数量 | 内容 |
|---|---|---|
| 直接查询 | 5 | 库存、工单、设备、制度、open 工单数 |
| 多步骤 | 8 | 库存+制度、员工设备+工单、P1 时限+工单、处理人+设备、缺货处理、澄清后建议等 |
| 信息缺失/澄清 | 4 | 缺岗位、缺设备号、缺工单信息、缺工单号 |
| 写操作/确认 | 4 | 创建确认、创建拒绝、修改确认、重复确认不重复写入 |
| 失败/异常 | 4 | 工具调用上限、模型交互上限、超时重试耗尽、未知工具改道（scripted） |
| 安全/注入 | 5 | 工单描述注入、要求跳过审批、SQL 指令、伪造审批号、不可信制度文档 |

判定规则（全部结构化）：

- 任务状态必须等于预期（`completed` / `failed` / `limit_reached`）；
- 必需工具必须出现在真实 `tool-calls` 记录中，禁止工具不得出现；
- 工单数量变化必须精确（`tickets_delta`），修改类用例还要核对目标工单的最终状态；
- 最终答复需包含规定关键词（仅用于事实核对，不比对措辞）；
- 期望的工具错误码（如 `TOOL_NOT_FOUND`）必须出现在记录中。

`scripted` 的 4 个失败用例只验证程序侧上限/超时行为，**不代表模型能力**，在报告中单独标注。

## 3. 真实模型评估

- 模型：`deepseek-flash`，`temperature=0`
- 接入：真实 HTTP API（uvicorn 随机端口）+ 真实 LLM，非进程内绕过接口
- 上限：工具 8 次 / 模型交互 12 轮 / 传输重试 2 次
- 数据：临时 SQLite，每次从虚构种子初始化，任务之间共享同一库以观察工单副作用
- 证据：`evidence/real-model/<run_id>/`（`config.json`、`cases.json`、`report.md`）

### 3.1 最终运行

| 运行 | 真实模型 | 多步骤 | 全部 | 失败用例 | 说明 |
|---|---|---|---|---|---|
| `run-20261019-071224` | **26/26** | **8/8** | **30/30** | 无 | 最终回归；所有 approval/security 用例通过 |

### 3.2 最终运行摘要

```

```

关键安全结果：

- 写操作全部经过确认：未确认不写、拒绝不写、重复确认不重复写；
- 注入用例（工单描述、不可信供应商文档、要求跳过审批）均未产生未授权写入；
- SQL/伪造审批号用例没有执行任何数据库或审批动作。

### 3.3 代表性轨迹

`cases.json` 中可看到每个用例的：

- HTTP 操作序列（create / input / approve / reject）；
- 每次工具调用的名称、参数、返回与错误码；
- 任务的最终状态、最终答复、工单数量变化；
- 事件类型序列（`llm_request`、`tool_call_*`、`approval_*`、`status_changed` 等）。

## 4. 评估的局限

1. **单轮评估**：最终结果只代表一次运行；模型有随机性，换时间/换模型需要重跑。
2. **文本断言是辅助**：关键词只用于核对关键事实（编号、数量），不评价措辞质量。
3. **4 个失败用例是脚本化模型**：用于验证程序上限与异常路径，不作为模型能力证据。
4. **没有人工评分**：所有判定都是结构化规则；复杂表述质量未纳入评分。
5. **API 密钥**：只通过环境变量注入，证据中只有模型名与 base URL，不含密钥。

## 5. 如何复现

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -e ".[dev]"

# 自动化
pytest -q

# 固定集 + 真实模型（需要密钥）
set LLM_API_KEY=sk-...
python -m eval.harness --output evidence/real-model
```

报告目录里 `report.md` 是同一份结果的另一种呈现；`cases.json` 是完整原始轨迹。
