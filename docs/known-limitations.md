# 已知限制

> 诚实地记录"没做"和"做不完美"的地方。这份清单也是后续演进的输入，不是免责声明。

## 1. 定位与范围

本项目是**虚构数据的企业 IT 服务台 Agent 演示**：

- 不连接真实 ERP、工单系统、资产系统或任何企业内网；
- 不执行真实采购、领用、资产变更或资金操作；
- 不适配企业 SSO、多租户、生产级权限平台。

## 2. 对模型的依赖

1. **工具调用质量取决于模型**：`deepseek-flash` 在固定测试集上 26/26，但换模型/换时间可能不同；`temperature=0` 只降低随机性，不保证完全可复现。
2. **没有多模型路由/降级**：模型服务不可用时，任务以 `failed` 结束并允许有限次 `resume`，不会自动切换备用模型。
3. **上下文会随步骤增长**：消息与工具结果原样回灌，未做摘要或裁剪；单任务上限 12 轮/8 次工具调用，避免无限膨胀，但超长工具结果仍可能挤占上下文。
4. **没有流式输出**：最终答复在任务结束后一次性返回，长任务需要轮询。
5. **没有成本核算**：不统计 token 或费用，只记录调用轮数与工具次数。
6. **提示注入只能缓解**：程序侧保证"写操作必须确认、工具白名单"，但模型仍可能被不可信文本误导去*提议*危险操作；这类提议会被确认环节拦住，不代表模型判断正确。

## 3. 并发与部署

1. **单进程假设**：任务锁是进程内 `threading.Lock`；`uvicorn --workers > 1` 或多副本部署时锁失效，可能重复调用模型（数据库写入仍幂等，但会浪费调用）。
2. **SQLite 单机**：WAL + `busy_timeout` 支持轻量并发，不适合多节点或高并发写入。
3. **没有任务队列**：任务在 API 进程的线程池执行；进程重启会丢失执行中的循环，遗留任务标记为 `failed(INTERRUPTED)`，需要显式 `POST /resume`。
4. **没有调度器**：失败任务不会自动重试；`limit_reached` 不允许自动续跑，需要新建任务。
5. **启动恢复是"标记"而非"继续"**：不承诺自动恢复，避免把半途状态当成成功。
6. **没有优雅排空**：关闭服务时不会等待后台任务完成；重启后按中断处理。

## 4. 安全边界

1. **没有认证/授权**：API 无 API Key、OIDC 或 RBAC，任何能访问端口的人都能创建任务、查看轨迹、确认写操作；只适合本地或可信内网。
2. **没有 TLS/速率限制**：公网部署必须在反向代理层补齐，并限制请求体大小。
3. **确认的崩溃窗口**：执行写操作与把 approval 标为 `executed` 不是同一个数据库事务（工具使用独立连接）。若进程恰好在两者之间崩溃，恢复后可能重复执行同一操作。正常重复确认已做幂等，但这个窗口未消除。
4. **操作人身份未校验**：`decided_by` 是请求里自报的字符串，不是经过认证的身份。
5. **审批凭证不是密码学签名**：`ApprovalToken` 由服务端根据 approval 记录重建，依赖数据库可信，不防数据库被直接篡改。
6. **没有敏感数据脱敏**：日志与轨迹会记录用户输入与工具返回（当前均为虚构数据）；接真实数据前需要脱敏与留存策略。

## 5. 状态与数据

1. **任务不会自动去重**：相同消息重复提交会生成不同 `task_id`（这是有意为之，方便多轮独立尝试）。
2. **消息只增不减**：`task_messages` 不做归档/清理，长期运行会持续增长。
3. **没有数据库迁移框架**：schema 用 `CREATE TABLE IF NOT EXISTS` 演进，复杂变更需要手工迁移。
4. **事件/轨迹查询有上限**：`/events` 默认最多 200 条、`/tool-calls` 返回全部（单任务最多 8 条）。
5. **工单数量随时间增长**：评测与试用会在库中创建真实（虚构）工单，没有重置接口。

## 6. 评估的局限

1. **最终评估是单轮**：只代表 `run-20261019-071224` 这一次；模型有随机性。
2. **4 个失败用例是脚本化模型**：只验证程序上限/超时/未知工具，不代表模型能力。
3. **文本断言是辅助**：关键词用于核对编号/数量等事实，不评价答复质量与措辞。
4. **没有人工评分**：全部判定为结构化规则，复杂业务正确性仍需人工抽查。

## 7. 刻意不做

- 多 Agent 协作与 Agent 间通信；
- 完整向量知识库与高级 RAG；
- 本地大模型部署、微调、推理优化；
- 真实企业系统接入、真实资金/资产操作；
- 企业 SSO、多租户、生产权限平台。

## 8. 如果继续演进

优先级从高到低：

1. 任务级数据库抢占 + 外部队列（支持多 worker / 重启续跑）；
2. 写操作与 approval 状态同事务（或引入幂等键到工具层），消除崩溃窗口；
3. API 认证、操作人身份与审批审计；
4. 消息摘要/裁剪与 token 成本统计；
5. 流式输出与任务事件订阅；
6. 工具结果与日志脱敏。
